# 보호 범위와 주의사항

## 막는 것

- 고정 협업 순서 없이 봇마다 별도 컨테이너·신원·구독 인증 홈을 사용합니다.
- 실제 Buzz/AI 프로세스는 사용자 10001로 실행합니다.
- 감독 코드만 컨테이너 root이며 SETUID·SETGID·KILL·CHOWN·DAC_OVERRIDE만 추가합니다.
- Docker socket, host PID/network, privileged 모드, 외부 관리 포트를 컨테이너에 제공하지 않습니다.
- root 전용 설정·상태·쿼터 디렉터리를 AI 프로세스가 읽거나 수정하지 못하게 합니다.
- SSH 배포 키는 전용 계정의 강제 명령으로 제한합니다. 수신기는 임의 셸·파일 경로·바이너리를 받지 않습니다.
- 제공자 설정에 비밀번호·토큰을 입력하지 않습니다. 봇 nsec는 Buzz의 공식 배포 payload로만 전달하며 SSH로 암호화합니다.
- 사람의 개인키와 같은 공개키를 가진 봇 배포는 거부합니다. 서버 설정에는 사람의 공개키만 필요합니다.
- 같은 공개키의 중복 컨테이너는 만들지 않습니다. 충돌한 이름의 다른 컨테이너는 수정하지 않습니다.
- 실행 중 봇의 구성 변경은 먼저 중지하도록 요구합니다.
- native 봇이 정상 종료하면 중지 상태를 디스크에 기록합니다. Docker가 감독 컨테이너를 다시 시작해도 AI를 자동 재실행하지 않습니다.
- 오류·호출 한도·시간 초과는 해당 봇을 held로 멈춥니다. 멈춘 봇은 자동 회복하지 않습니다.
- 첫 구독 로그인 전에는 needs_login으로 대기합니다.

## 막는다고 주장하지 않는 것

**이 코드는 적대적인 코드를 완전히 가두는 전용 보안 샌드박스가 아닙니다.**
컨테이너가 모든 커널 취약점·공급망 공격·외부 유출을 막아주는 것은 아닙니다.

공식 Buzz는 도구 승인을 자동 허용할 수 있습니다. 이 패키지는 개별 셸 명령 승인 UI를 추가하지 않습니다.
AI는 자기 홈과 작업 폴더를 읽고 쓸 수 있고, 자기 구독 인증과 자기 봇 신원을 사용하는 프로세스입니다.
작업 파일·외부 웹 내용의 악성 지시로 자기 자격증명이 유출될 위험이 남습니다. 외부 네트워크도 기본 허용입니다.
실제 서비스 결제·게시·관리자 권한이나 중요한 개인 자료는 초기 실험 봇에 주지 마세요.

ACP guard가 세는 단위는 `session/prompt` 시작 횟수입니다.
CLI 내부의 API 재시도, 하위 AI, 쉘에서 직접 실행한 별도 CLI, 도구 내부 통신은 모두 세지 못합니다.
작업이 응답을 끝낸 뒤 따로 남긴 백그라운드 프로그램도 1회 prompt 시간 제한만으로 통제되지 않습니다.
따라서 이는 실수로 일어나는 자동 대화 반복을 줄이는 운영 장치이지 정확한 토큰/요금 상한이나
악의적인 AI에 대한 통신 강제 차단 장치가 아닙니다.

정상적인 native 종료/held 상태 뒤에는 감독 프로세스가 컨테이너를 종료하므로 남은 프로세스도 정리됩니다.
그러나 커널이나 Docker 자체가 응답하지 않는 상황까지 보증하지 않습니다.

## 자유 협업과 접근 권한

봇간 호출은 Buzz의 공식 ACL(접근 허용 규칙), 채널 참여, Nostr 멘션 태그에 따릅니다.
`owner-only`가 같은 소유자의 봇을 허용하는 버전이 있으므로 사람만 허용한다는 의미로 사용하지 마세요.
이 패키지는 native ACL을 다시 구현하지 않습니다. 특정 동료 봇만 허용해야 한다면 실제 버전의 동작을 시험해야 합니다.
`anyone`은 v0.2에서 거부하고, `owner-only`/`allowlist`/`nobody`만 지원합니다.

봇끼리 기다릴 수 있으므로 전역 AI 실행 잠금은 두지 않았습니다.
한 봇 내부 prompt는 하나씩 전달하지만, 여러 봇은 병렬로 실행할 수 있습니다.
공유 workspace는 동시 파일 수정 위험을 갖습니다. 기본은 봇별 private이며 명시적으로 같은 그룹을 설정할 때 공유합니다.

## 재부팅

정상적인 Docker Stop 신호는 다음 시작을 위한 ready 상태를 남깁니다.
수동 Docker Stop 자체의 자동 재시작 여부는 Docker의 정책을 따릅니다.
`!shutdown`처럼 native 프로그램이 정상 종료한 경우는 stopped를 유지합니다.
강제 재부팅·OOM·감독 프로세스 강제 종료 뒤 running 기록만 남으면 held로 보류합니다.
실행 중 작업을 자동 재시도하거나 완료로 처리하지 않습니다. 사람의 확인이 필요합니다.

## 인증과 모델 설정

공식 CLI 로그인만 사용합니다. 사용자 정의 API 키·Base URL·셸 실행·환경 변수 주입은 기본 계약에서 거부합니다.
선택한 모델·역할·노력 수준은 허용한 native 환경 키를 통해 전달합니다.
알 수 없는 환경 설정을 조용히 무시하지 않고 배포를 거부하므로, 특정 최신 앱 설정은 추가 지원이 필요할 수 있습니다.
계정의 구독 한도·추가 크레딧·자동 충전은 이 코드가 바꾸지 않습니다.

한 계정으로 여러 봇을 로그인해도 사용량이 봇 수만큼 늘어나는 것은 아닙니다.
각 봇의 갱신 파일을 보존하고 인증 실패 시 재로그인합니다. 72시간 검증만으로 장기 갱신 안정성을 단정하지 않습니다.

## SSH 설치 변경 범위

설치 스크립트는 전용 계정과 sudo 규칙을 추가합니다. 이는 호스트 보안 설정 변경이므로 검토 후 실행해야 합니다.
설치 스크립트가 방화벽·sshd 전체 설정·기존 계정·buzz-rpka를 변경하지는 않습니다.
Windows의 SSH 개인키가 유출되면 공격자가 허용된 봇을 재배포할 수 있으므로 암호화·ssh-agent·키 회수가 필요합니다.
암호·nsec·토큰이 들어간 config.json, 호스트 백업 및 ~/.ssh를 공개 저장소나 영상에 넣지 마세요.

## 실측 전제

기본 메모리 예산 5,120MiB는 설계값입니다. 기존 Relay·DB·MinIO·운영체제의 사용량을 측정해서 조정해야 합니다.
봇 8개라는 등록 상한은 8개 동시 실행 성능 인증이 아닙니다.
외부 공급망, Ubuntu/Node/Python 보안 업데이트와 최종 이미지 지문을 운영자가 관리해야 합니다.
