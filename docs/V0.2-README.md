# buzz-agents v0.2.0 — Buzz 기본 멀티 봇 + Hostinger VPS 실행

**v0.1.0의 Codex → Claude → Codex 고정 작업 흐름을 제거한 직접 작성 코드입니다.**

Buzz에서 봇을 만들고, 봇마다 Codex 또는 Claude 연결 프로그램과 역할·모델을 지정합니다.
이 패키지의 `Hostinger VPS — Native Buzz` 원격 실행 제공자를 선택하면,
해당 봇의 공식 `buzz-acp`가 Windows가 아니라 VPS의 독립 컨테이너에서 실행됩니다.
모든 대화·멘션·컨텍스트·응답은 공식 Buzz가 처리합니다. 이 프로그램은 협업 순서를 정하지 않습니다.

## 제공 파일

| 구성 | 역할 |
|---|---|
| `bin/buzz-backend-hostinger.exe` | Windows x64용 원격 배포 연결 모듈. 실제 교차 빌드됨. 코드 서명되지 않음 |
| `bin/buzz-backend-hostinger` | Linux x64용 같은 연결 모듈. 로컬 info 실행 검사됨 |
| `provider/` | 위 모듈의 Go 원본 코드·테스트. 외부 Go 의존성 없음 |
| `buzz_agents/host.py` | VPS의 제한된 SSH 배포 수신기. Docker를 사용하는 유일한 관리 구성 |
| `buzz_agents/native.py` | 봇별 상주 프로세스, 최초 로그인 대기, 의도적 종료 유지 |
| `buzz_agents/guard.py`, `policy.py` | 공식 ACP 통신을 전달하면서 실행 시간·호출 횟수·오류 중단만 통제 |
| `buzz_agents/scheduler.py` | 선택 기능. 정해진 시각에 특정 봇을 Buzz에서 멘션 |
| `docs/DEPLOYMENT.md` | 최초 설치, Windows 연결, Buzz 내 봇 생성·실행 절차 |
| `docs/MIGRATION.md` | v0.1.0과 충돌 없이 교체하는 절차 |
| `docs/SECURITY.md` | 보호 범위와 남은 위험 |
| `docs/VERIFICATION.md` | 실제 수행한 검사와 수행하지 않은 검사 |

## 자유롭게 가능한 구성

예를 들어 `기획자=Codex`, `작가=Claude`, `검토자=Claude`, `개발자=Codex`처럼
각각 다른 신원·역할을 구성할 수 있습니다. 같은 종류의 봇을 둘 이상 만들어도 됩니다.
이 예는 지원 형태를 설명한 것이며, KVM 2에서 네 봇을 동시에 안정적으로 돌렸다는 측정 결과는 아닙니다.

누가 먼저 일하고 누가 검토할지는 사용자의 지시와 Buzz의 협업 동작에 맡깁니다.
봇이 직접 다른 봇을 호출하는 데 필요한 멘션·채널·접근 권한도 Buzz에서 설정해야 합니다.
실제 상호 호출은 공식 Buzz/ACP 버전 조합으로 별도 확인해야 합니다.

**전역에서 AI를 하나씩만 실행하는 잠금은 없습니다.** 한 봇이 다른 봇의 답을 기다리는 자유 협업에서
전역 잠금은 교착 상태를 만들 수 있기 때문입니다. 대신 봇 하나의 동시 턴은 1개로 제한합니다.

## 적용 순서

1. `docs/DEPLOYMENT.md`에 따라 VPS에서 이미지를 한 번 빌드하고 배포 수신기를 설치합니다.
2. Windows에 제공된 `.exe`를 넣고, 이 VPS만 접근하는 제한된 SSH 연결을 준비합니다.
3. Buzz 봇의 실행 위치에서 **Hostinger VPS — Native Buzz**를 선택합니다.
4. Codex 또는 Claude, 모델·역할·접근 범위를 설정하고 배포합니다.
5. 새 봇은 **needs_login** 상태에서 대기합니다. 해당 컨테이너 터미널에서 공식 구독 로그인을 합니다.
6. 로그인 명령이 성공하면 실행을 시작합니다. 실제 메시지 응답을 확인한 뒤 Windows 종료 시험을 합니다.

**ZIP을 Buzz에 가져오기만 하면 설치되는 플러그인은 아닙니다.** 최초에는 VPS 실행 이미지·제한된 SSH 수신기와
Windows 원격 제공자 설정이 필요합니다. 그 이후 봇별 배포 설정을 Buzz에서 전달하는 구조입니다.

## 버전과 UI 전제

공식 Buzz의 `info/deploy` 제공자 규약과 `launch` 블록을 처리합니다.
사용자의 앱에 원격 실행 위치 선택이 없거나 `launch` 블록을 보내지 않으면 거부합니다.
이 경우 로컬 설정을 추측해 VPS에 복사하거나 Windows 실행으로 몰래 대체하지 않습니다.

봇을 그냥 `Local`로 만들면 Windows에서 실행됩니다. 반드시 이 원격 제공자를 선택해야 합니다.
동일한 봇의 개인키를 Windows 로컬 실행기와 VPS에서 동시에 실행하지 마세요.

역할·모델 수정은 **저장만으로 실행 중인 VPS에 실시간 반영되지 않습니다.** 먼저 소유자가 해당 봇에
`!shutdown`을 보내 종료한 뒤, 수정한 설정으로 다시 배포합니다. 같은 설정의 실행 중 봇 재배포는 중복 생성하지 않습니다.

## 안전장치의 의미

봇별 기본값은 1회 턴 1,800초, 1시간 내 턴 시작 20회, 최근 24시간 내 턴 시작 100회입니다.
이는 제품 성능 수치가 아니라 수정 가능한 초기 정책입니다.

제한 도달이나 ACP 오류가 발생하면 해당 봇이 `held`로 중단됩니다. 다른 봇의 협업 순서를 바꾸지 않습니다.
쿼터 기록은 재배포해도 지워지지 않습니다. 한도 자체를 명시적으로 바꾸거나 시간이 지난 뒤 재배포해야 합니다.

이 숫자는 **모델 토큰 수나 비용 상한이 아닙니다.** CLI 내부 재시도·하위 에이전트·도구 실행을 모두 계수하지 않습니다.
자동 결제/추가 사용량 여부는 각 계정에서 별도로 확인해야 합니다.

## 파일 공유

기본 `workspace=private`는 봇별 작업 폴더입니다. 공동 파일을 사용하려면 같은 봇들의 제공자 설정에
예를 들어 `workspace=webtoon`을 입력합니다. 이 값이 같은 봇들은 같은 `/workspace`를 봅니다.
공유 작업 폴더에는 강제 파일 잠금이 없습니다. 동시 수정 충돌을 피하는 역할 분담이나 Git 브랜치가 필요합니다.

각 봇의 구독 인증 홈은 항상 분리됩니다. 다른 봇의 로그인 파일을 복사해서 재사용하지 않습니다.

## 검증 상태

Python/Go 테스트 및 가짜 ACP 실행기 연동 검사를 수행했습니다. Windows `.exe` 교차 빌드도 성공했습니다.
**실제 Docker 이미지 빌드, Windows Buzz UI에서 제공자 선택, Hostinger 배포, 실제 구독 인증,
실제 AI 간 위임, Windows 종료·장시간·VPS 재부팅 시험은 아직 수행하지 않았습니다.**

이 패키지는 실제 VPS에 단계적으로 적용할 후보이며, 운영 검증이 끝난 완제품이라는 주장은 하지 않습니다.
기존 `buzz-rpka`는 수정하거나 삭제하지 않습니다. 새 Docker 프로젝트 이름은 `buzz-agents-v2`입니다.
