# Buzz VPS 연결 도우미 시작하기

**v0.3.0 시험용: 실제 Windows·Hostinger 통합 시험 전입니다.**
현재 결과물은 개발 후보입니다. 시청자 배포용 완성품으로 소개하지 마세요.

## 준비

- 기존 Buzz Relay가 설치된 Ubuntu Linux x64 VPS. Docker, Docker Compose, Python 3, sudo가 필요합니다.
- Windows x64와 OpenSSH 클라이언트(Windows 선택적 기능).
- VPS IP, SSH 포트, 기존 root SSH 접속 수단. 도우미가 비밀번호를 저장하지 않습니다. 관리자 SSH를 막아 둔 서버의 보안을 낮추지 마세요.
- Windows Buzz에서 사용하는 `wss://...` Relay 주소.
- Relay 소유자의 64자리 HEX **공개키**. `nsec` 개인키는 입력하지 않습니다.
- Codex / Claude 사용 권한이 있는 개인 계정. 플랜 사용량 제한은 그대로 적용됩니다.

이 도우미는 Hostinger 또는 Buzz의 공식 설치 프로그램이 아닙니다. 기존 Buzz 원격 제공자 규약을 사용하는 커스텀 연결 도구입니다. 서명되지 않은 시험용 실행 파일이며, 보안 기능을 전역으로 끄도록 요구하지 않습니다.

## 1. 서버 설치·연결

1. `Buzz-VPS-Setup.exe`를 실행합니다. 브라우저 관리 화면이 아닌 메뉴 방식의 콘솔 프로그램입니다.
2. **1. 최초 서버 설치·연결**을 선택하고 위 정보를 입력합니다.
3. 설치 대상 VPS가 맞으면 `설치`를 입력합니다.
4. SSH가 처음 연결되면 서버 지문을 확인합니다. Hostinger 웹 콘솔에서 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`로 확인한 지문과 일치할 때만 승인합니다. SSH가 다른 키 종류를 제시하면 그 종류의 호스트 공개키 지문을 확인하세요.
5. SSH가 요구하는 root 비밀번호 등 기존 접속 절차를 진행합니다. 검증 접속과 설치 접속에서 각각 요청될 수 있습니다.
6. 완료까지 기다립니다. 도우미가 자체 서버 소스를 전송하고 Docker 이미지를 빌드합니다. 처음에는 다운로드·컴파일 시간이 필요합니다.

기존 `buzz-rpka`, Traefik, Relay 데이터는 편집하지 않습니다. 신규 전용 사용자 `buzzdeploy`, `/opt/buzz-agents`, 전용 sudo 규칙과 제한된 SSH 키를 구성합니다. 도우미는 기존 SSH 로그인 방식을 변경하지 않습니다.

Windows에는 `%USERPROFILE%\.buzz-agents\`의 전용 연결 설정/키/known_hosts와 `%USERPROFILE%\.local\bin\buzz-backend-hostinger.exe`를 생성합니다. 전역 SSH config 및 Windows의 AI 로그인 파일은 건드리지 않습니다. 전용 키는 암호 없이 생성하되 사용자 파일 권한을 제한하고 서버에서 허용 명령을 제한합니다. Windows 계정 접근자는 해당 봇 배포·로그인·예약 권한을 사용할 수 있으므로 키를 다른 사람에게 주지 마세요.

서버 폴더나 연결기 버전이 다르면 덮어쓰지 않고 중지합니다. 기존 v0.2가 이미 설치되어 있으면 이 도우미로 바로 업그레이드하지 마세요.

## 2. 기존 Windows Buzz에서 봇 만들기

1. Buzz를 완전히 종료하고 다시 엽니다.
2. Codex 봇과 Claude 봇을 각각 만듭니다.
3. 실행 위치는 **Hostinger VPS — Native Buzz**를 선택합니다. `Local`은 Windows 실행입니다.
4. 실행기는 각각 `codex-acp`, `claude-agent-acp`, 연결 별칭은 `buzz-vps`입니다. 나머지 제한은 기본값으로 시작합니다.
5. 두 봇이 파일을 함께 사용하려면 두 봇 모두 `workspace=team`으로 지정합니다.
6. 각 봇을 배포합니다. 최초에는 `needs_login`으로 대기합니다.

실행 위치 메뉴가 없거나 배포가 거부되면 앱 버전과 원격 제공자 지원 여부를 확인해야 합니다. 도우미가 Buzz를 패치하거나 자동 업데이트하지 않습니다. 봇을 로컬로 실행해 대신 성공으로 처리하지 않습니다.

## 3. VPS에 로그인하기

1. 도우미에서 **2. VPS의 Codex / Claude 로그인**을 선택합니다.
2. 목록에서 인증할 봇을 선택합니다.
3. 출력되는 **공식 로그인 주소**를 Windows 브라우저로 열고 해당 계정으로 승인합니다.
4. 인증 코드 입력이 요구되면 도우미 창에 입력합니다. 이 화면은 녹화하거나 공유하지 않습니다.
5. Codex와 Claude 봇 각각 진행합니다. Codex 기기 코드 로그인은 계정 보안 설정에서 허용이 필요할 수 있습니다.
6. Buzz에서 각 봇을 멘션해 실제 응답을 확인합니다.

로그인 명령은 VPS의 해당 컨테이너 안에서 실행됩니다. 인증 파일은 VPS의 봇별 영구 폴더에 남습니다. Windows 로컬 Codex/Claude 로그인 정보를 복사하지 않습니다. 같은 종류의 봇을 추가할 때도 현재 구현은 봇마다 인증합니다.

`running`은 프로세스가 실행 중이라는 뜻입니다. 플랜 인증·실제 모델 응답 성공을 보장하지 않습니다. 실행 중인 봇을 재인증하려면 먼저 Buzz에서 소유자가 `!shutdown`으로 중지합니다.

## 4. 협업

두 봇을 같은 Buzz 채널에 추가합니다. 봇 접근 설정을 allowlist로 사용하고 **상대 봇의 공개키를 서로 허용**합니다. 설정 변경 뒤에는 중지 후 재배포가 필요합니다. 작업 폴더를 공유해도 동시 파일 편집의 충돌을 자동으로 해결하지는 않습니다.

작은 과제부터 지시합니다. 예: Codex가 파일을 작성하고 Claude가 검토한 뒤 결과를 채널에 보고하도록 합니다. Relay 연결이나 두 봇의 online 표시만으로 협업 성공으로 판단하지 않습니다.

## 5. Windows 종료 뒤 새 작업 시작하기 (선택 예약)

도우미의 **4. 매일 예약 설정**을 사용합니다. 예약 자체는 VPS에서 실행되므로 도우미나 Windows를 켜 둘 필요가 없습니다.

최초 설정에서 표시되는 예약 발신자 공개키를 Buzz Relay 회원·대상 채널에 추가하고, 대상 봇의 allowlist에도 허용해야 합니다. 도우미가 사람의 nsec를 받아 이 권한을 자동 부여하지 않습니다. 권한 설정 전에는 예약 활성화를 취소하세요.

대상 봇, 채널 UUID, 한국 시간 `HH:MM`, 작업 문장을 입력합니다. 첫 버전은 **매일 예약 1개**이며 다시 저장하면 기존 도우미 예약을 교체합니다. 5번 메뉴는 예약만 중지하며 이미 시작한 AI 작업을 취소하지 않습니다.

시험할 때는 몇 분 뒤의 시각으로 설정하고, **예약 시각 전에 Windows를 완전히 종료**합니다. 이후 채널 결과와 VPS의 작업 파일·시간을 확인합니다. 전송 성공은 AI 작업 완료와 다릅니다. 꺼져 있거나 held인 봇을 자동 재시작하지 않으며, 2분 이상 지연된 예약을 몰아서 재실행하지 않습니다.

## 실패·복구

- 같은 소스·서버·공개키 정보로 재실행하면 이미 완료된 서버 설치를 인식합니다.
- 설치 도중 실패해 `/opt/buzz-agents`는 존재하지만 설치 표식이 없으면 자동 덮어쓰지 않습니다. 관리자 점검이 필요합니다.
- SSH 지문 변경은 자동 수락하지 않습니다. 실제 서버 키 변경 여부부터 확인합니다.
- `held`: 장애 또는 한도 중단. 원인 해결 후 Buzz에서 명시적으로 재배포합니다. 사용량 기록은 초기화하지 않습니다.
- 인증 만료·취소: 해당 봇을 중지하고 2번으로 재인증합니다.
- Docker 재시작으로 인증 홈과 작업 폴더는 유지하지만, 진행 중이던 작업의 자동 복구를 보장하지 않습니다. 강제 종료는 held로 남을 수 있습니다.

## 아직 남은 실제 합격 시험

새 Windows 설치, 실제 VPS Docker 빌드, 공식 계정 로그인·갱신, Buzz 원격 메뉴·멘션, 두 AI 파일 협업, Windows 종료 후 예약 작업 완료, KVM 2 CPU/RAM 측정, 정상/강제 재시작을 확인해야 합니다. 현재 ZIP을 받았다는 사실만으로 이 시험이 통과한 것은 아닙니다.
