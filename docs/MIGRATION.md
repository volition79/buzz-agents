# v0.1.0에서 v0.2.0으로

## 아직 v0.1.0을 설치하지 않은 경우

v0.1.0은 설치하지 않습니다. v0.2.0의 DEPLOYMENT.md를 따릅니다.
기존 `buzz-rpka`는 그대로 유지합니다.

## v0.1.0을 이미 설치한 경우

1. v0.1.0 작업 장부에서 실행 중 작업·예약을 확인하고 일시정지합니다.
2. 진행 중 작업은 실제 결과와 파일을 확인한 뒤 종료합니다. 운영 중 무조건 삭제하지 않습니다.
3. 기존 `buzz-agents` 프로젝트를 Stop 합니다. 볼륨은 삭제하지 않습니다.
4. 기존 작업 폴더·인증 홈·장부를 별도로 백업합니다.
5. v0.2.0은 `/opt/buzz-agents`, `/var/lib/buzz-agents-v2`, 새 프로젝트 `buzz-agents-v2`를 사용합니다.
6. v0.1.0 신원과 겹치지 않는 새 봇을 Buzz에서 만들어 먼저 시험합니다.
7. 필요한 일반 작업 파일만 검토 후 새 workspace에 복사합니다. `.codex`, `.claude`, 토큰 파일을 봇들 사이에 복제하지 않습니다.

v0.1.0의 고정 작업 장부는 자동으로 native 대화 세션으로 변환하지 않습니다.
이전 `/ba run`, `/ba pause`, `/ba retry` 명령도 v0.2.0에서 제공하지 않습니다.
옛 명령은 새로운 봇에게 전달해도 일반 텍스트일 뿐입니다.

## 동일한 봇 신원을 유지하려는 경우

한 개인키에 두 실행기를 동시에 붙이면 중복 응답 위험이 있습니다.
Windows Local 실행기와 v0.1.0 실행기를 확실히 중지한 뒤 해당 봇을 이 원격 제공자로 배포해야 합니다.
자동으로 옛 키·구독 인증·봇 기록을 가져오는 마이그레이션 기능은 구현하지 않았습니다.

## 롤백

v0.2.0 봇들을 먼저 종료하고 `buzz-agents-v2` 컨테이너를 Stop 합니다.
기존 v0.1.0 데이터는 손대지 않았으므로 별도로 검토한 뒤 필요할 때 다시 시작할 수 있습니다.
두 버전의 동일 신원 실행기를 동시에 켜지 않습니다.

## 이미지·코드 업데이트

전체 봇을 종료하고 백업한 뒤 새 이미지의 preflight와 실제 작은 작업을 검사합니다.
`/opt/buzz-agents/host/settings.json`의 image/image_id는 root 운영자가 함께 갱신해야 합니다.
이미지 태그만 덮어쓰면 기존 기록과 다른 Image ID라 배포가 거부됩니다.
살아 있는 봇의 이미지도 자동 교체하지 않습니다.
호스트 관리 코드도 새 버전과 맞춰 교체하되, settings.json과 /var/lib 상태를 덮어쓰지 않습니다.
자동 업데이트, 데이터 삭제, `--remove-orphans`는 사용하지 않습니다.
